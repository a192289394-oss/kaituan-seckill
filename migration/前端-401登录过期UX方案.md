# 开团页 401 / 登录过期 UX 方案（前端评估 · 先不改生产）

经暖暖委派。现网：https://1.12.208.101/kaituan/  
源码：`server/static/app.js`（`api` 401 分支 + `refresh` catch）

## 问题

登录过期（`401` 或跳到 `/site/login`）时：

1. `api()` 抛「访问验证已失效…」并展开本地「连接任务入口」凭证框；
2. `refresh()` 的 **通用 catch** 仍执行：顶栏改成「最新收单与环境状态无法读取」、`renderRuntimeHealth({})` → Android / root / 来客 / 原生接口四个全是 **「未确认」**、写入闸「运行环境状态无法读取」。

操作员观感：像 Mac/模拟器/来客全炸了，其实只是 **网页登录过期**，环境根本没读到。

## 结论（建议做）

**应当：登录过期时强引导主站/经营台登录，并弱化环境「未确认」噪声。**  
真网络故障、Mac 离线、来客掉登仍走现有环境人话，不要混进鉴权失败。

## 推荐交互

| 场景 | 顶栏主文案 | 环境四格 | 登录引导 |
|---|---|---|---|
| **A. 鉴权失败 401 / 跳登录页** | 「登录已过期，请先登录后再打开本页」 | 折叠或显示「登录后才能读取」/「—」，**禁止**刷「未确认」 | 主按钮链到主站登录（现网 `/` 或 `/site/login`；迁 dashboard 后用经营台登录页）。本地 kaituan token 框降级为次要/过渡（产品已定跟经营台同登录） |
| **B. 网络/超时/5xx** | 保持现「无法读取…」 | 可「待更新」，勿伪装成已核验 | 刷新重试 |
| **C. 已登录但 Mac/来客未就绪** | 继续用 `write_ready` / `human_reason` | 正常四格 | 无登录引导 |

## 前端改法（草案，待架构同意再动）

1. `api()` 401 时给 `UserError` 打标，如 `code: 'auth_expired'`（或 `status === 401`）。
2. `refresh()` catch 分支：若鉴权失败 → 调新函数 `renderAuthExpired()`：
   - 顶栏 bad/warn：「登录已过期…」+ 链到主站登录；
   - **不** `renderRuntimeHealth({})`；改为隐藏 details 或四格「登录后读取」；
   - `setWriteEnvironment(false, '请先登录后再提交')`；
   - 任务区一句「登录后自动恢复」，勿暗示模拟器故障。
3. 非鉴权失败仍走现 catch。
4. **不改**：提交语义、拒建、只提交一次、掉登停写（那是执行端 residency，不是网页 401）。

## 需架构拍板

- 401 时跳转/链接的 **最终登录 URL**（现网 vs 迁入 `dashboard.keyframe-gz.com`）。
- 同域挂载后 cookie 会话怎么续；本地 token 面板是否可下线。
- 同意后再改 `app.js`、备份、姐姐同步；产品验收「过期只像要登录，不像服务炸」。

## 风险

改错分支可能把真离线也收成「去登录」。必须以 `401` / 登录跳转为准，其它错误不进 A。

## 架构拍板（2026-10-16）

- **同意做**场景 A：401 / 跳 `/site/login` 时按本方案改 UX；**先不改生产**，等暖暖转用户拍板后再动。
- **现网登录 URL**：`https://1.12.208.101/site/login?next=/kaituan/`（优先用 API 返回的 `login_url`，没有再用此默认）。
- **迁 dashboard 后**：换成经营台登录页；本地 kaituan token 面板降级/可下线（产品已定跟经营台同登录）。
- **两层鉴权勿混**：外层主站会话（`X-Site-Login`）→ 内层 `gateway_session`（12h）。过期引导先主站，再谈开团凭证。
- **不改**：提交一次、拒建、worker token、写入闸语义。
