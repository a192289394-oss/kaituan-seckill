## 它是干什么的

**网页下单 → Mac 来客执行 → 回网页。**

目标是：你在网页上填一张开团或秒杀单，你自己的 Mac 把单子领走，在 Mac 里的安卓模拟器打开“来客”App 去执行，做完把结果和截图证据写回网页。这是目标，**仓↔现网对齐完成后**才能宣称装出来的能力与现网一致。`TODO(对齐后)`

## 你要装的是“一套”

**一套 = 1 台服务器（网页）+ 1 台 Mac（干活的）。**

- 服务器：放网页，收单子，记录结果。
- Mac：装安卓模拟器和来客 App，真正去点、去提交。
- 想要两套互不影响的环境？**就再装一套**（另一台服务器入口 + 另一台 Mac），两套各用各的密码和名字。

## 开始前准备好

| 东西 | 说明 |
|---|---|
| 一台 Linux 云服务器（Ubuntu） | 能装 nginx、python3 |
| 一个域名 + HTTPS 证书 | 例如 `gateway.example.com` |
| 一台 Mac | 长期开机、不休眠 |
| BlueStacks 安卓模拟器 | 实例名要叫 `Tiramisu64`，需 root |
| 来客 App 安装包 | 自己准备，仓库里没有 |
| frida-server 16.7.19 | 自己准备，仓库里没有 |
| 酒店目录 `catalog.sqlite3` | 酒店目录种子库（表 `merchant_catalog`）。自己准备一份**同结构**的 sqlite：业务导出，或从已有环境拷贝这份种子。worker 启动时只读拷进 `worker.sqlite3` 一次；没有这个文件则目录为空、不会崩。仓库里没有从 `merchant-*.json` 生成它的脚本，本轮也不做导入功能。 |
| 一个来客账号 | **你自己在模拟器里手动登录** |

## 六步装好

1. **生成两把钥匙**（在任意电脑上跑两次，得到两串不一样的字符）：
   `python3 -c 'import secrets;print(secrets.token_urlsafe(32))'`
   第一串叫“网页登录钥匙”，第二串叫“Mac 干活钥匙”。**两把必须不一样**，谁都别发到群里。
2. **装服务器**：按 [AI-INSTALL.md](AI-INSTALL.md) 第 6 章，把两把钥匙和你的域名填进 `gateway.env`，装好 systemd 服务和 nginx。
3. **打开网页试登录**：浏览器访问 `https://你的域名/kaituan/`，看到“连接任务入口”，输入“网页登录钥匙”，能进去就对了。
   （默认就是网页自己的登录，不需要接任何别的网站登录系统。）
4. **装 Mac 的安卓环境**：按 [install-mac-android-runtime.md](install-mac-android-runtime.md) 一步步做：模拟器 → 连接 → root → frida → 装来客 → **手动登录来客**。
5. **装 Mac 干活程序**：按 [AI-INSTALL.md](AI-INSTALL.md) 第 7 章：装 Python 依赖，把“Mac 干活钥匙”写进凭证文件（权限 0600），把服务器地址设成 `https://你的域名/kaituan`、Mac 名字设成 `mac-worker-1`（要和服务器里填的一样）。若有酒店目录种子，放到 `work/trigger-worker/catalog.sqlite3`；没有也能启动，目录为空。
6. **先试连接，再常驻**：先跑 `probe`，网页上看到“Mac 收单在线”；再跑 `install` 让它开机自动运行。

## 怎么算“安装骨架过了”

分两关。两关都过，仍然**不得**验收为「能力等同现网」。`TODO(对齐后)`

- **第一关 · 连上了**：网页能登录；网页显示 Mac 在线。
- **第二关 · 按目标清单做受控读回**：网页上 安卓 / root / 来客 / 接口 各自显示就绪；先下一张“只读”单；再用测试计划各走一张开团单、一张秒杀单，各**只提交一次**，并且回头查平台。读回只说明本环境按目标清单走到了这一步。**仓↔现网对齐完成前**，不得把这一关说成现网开团/秒杀能力。

## 系统自带的安全刹车（不能关）

完整规则见同目录 [risk-rules.md](risk-rules.md)。下面是给人看的摘要，不代替那份清单。

- 每张单只提交一次，已提交的只查不重发。
- 秒杀只往**已有**活动里加人，没有活动**绝不新建**。
- 来客掉登录、模拟器没准备好 → 自动停，不乱写。
- 连续失败 3 次（15 分钟内）→ 停。
- 每个账号每小时最多 6 次，整台 Mac 每小时最多 20 次，两次之间至少隔 60 秒。
- 不知道的数据显示“未知”，不会当成 0。
- “Mac 在线”≠“能干活”，网页会分开显示。

## 常见问题

| 遇到 | 先试 |
|---|---|
| 网页登录总失败 | 钥匙复制多了空格？浏览器地址要和 `gateway.env` 里的域名完全一样（https）。 |
| 登录后一刷新又要登录 | `GATEWAY_COOKIE_PATH` 要填 `/kaituan/`，并且全程用 https。 |
| Mac 一直不在线 | Mac 凭证里的钥匙和服务器“Mac 干活钥匙”是否一致；凭证文件权限是否 0600。 |
| Mac 报“bound to a different worker” | Mac 名字和服务器里 `GATEWAY_WORKER_ID` 不一致，改成一样。 |
| Mac 在线但单子不动 | 看网页上安卓/来客是否就绪；来客是否掉登录。 |
| 秒杀单说“没有活动” | 正常保护：先在平台上有生效活动再下单。 |

## 不要做的事

- 不要从别人的机器上拷 `gateway.env`、凭证、`queue.sqlite3`、`worker.sqlite3`、来客登录态来用——这些每套都**自己新生成**。酒店目录种子 `catalog.sqlite3` 按上面的表自备同结构文件，不要把它和那几份库混成一件事。
- 不要两套环境共用一个 Mac 名字或同一把钥匙。
- 不要让程序自动登录来客账号。
- 不要照抄文档附录里标着 `EXAMPLE_LIVE_ONLY` 的 IP、域名、Mac 名字——那是别人的现网环境。
