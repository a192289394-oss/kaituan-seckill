# Design System: 开团与秒杀任务工作台

## Mode and hierarchy

这是 Operate 工作台。用户先看 Mac 是否收单，再分别看 Android、root、来客 App 与原生接口状态，然后查看每张任务的明确结论、下一步和业务证据，最后才展开技术详情。界面不能把“已收单”“有心跳”“进程存在”或“已进入提交边界”表达成运行环境就绪或平台业务成功。

深色为默认主题，浅色可切换并保存在本机。两个主题共用同一层级：页面背景、面板、次级表面和边线；青色只用于主要操作、链接、焦点和选中状态。成功、等待与失败始终同时显示文字和颜色。

## Layout

页面最大宽度为 1360px。桌面采用 340px 新建任务区和弹性任务区，两列间距 32px；1050px 以下左列缩至 300px；760px 以下改成单列，页面水平内边距为 16px。

任务是有边界的操作面板。状态、摘要、处理方式和更新时间在首屏可见；需要补充时在原任务展开表单。确认操作使用原生 `dialog` 保护焦点和键盘顺序。

商品核对属于任务正文，不藏在技术 JSON 中。旧模板核对和当前候选使用真实表格；窄屏内表格在有边界的可聚焦区域横向滚动，页面本身不得产生横向滚动。

## Components and states

- 所有按钮最小高度 44px，焦点使用 2px 主题色轮廓和 3px 外偏移。
- 顶部主状态只表达“Mac 收单在线/离线”。Android、root、来客 App 与原生接口分别显示；原生进程存在但没有执行前 attach 时显示“任务执行前复核”。
- 只有收单在线、Android 可连接、root 已确认、来客 App 运行且原生接口可用或处于指定的执行前复核状态时，才允许勾选新写任务。其它状态仍允许提交只读核验。
- `waiting_review` 与 `waiting_device` 提供“立即只读复核”。确认文案明确只重新读取状态，不会再次发送保存、同意或创建请求；请求只调用 retry 接口并带当前 revision。
- 任务卡正文优先显示后端清洗后的真实结果或原因。酒店目录不唯一、身份缺失等原因不能藏在固定状态文案或技术详情里；目录建议与原任务身份的边界必须同时说明。
- 当前商品核对把旧模板精确命中、接口未返回、条件未通过和仍有未知项分开。未返回只表示未知，不能推断停售或库存。
- 当前候选显示商品售价和“平台建议秒杀价（未确认）”。新商品明确标记“未授权”，不在表格中提供提交或替换入口。
- 后端 `avail_qty` 不作为库存展示。需要说明供给字段时统一称“可售量”。
- 技术详情保留任务 ID、revision 与原始结果，但不重复整块商品核对数据。
- 加载、网络错误、登录失效、空列表、无搜索结果、禁用和提交中都有文字反馈；动态任务区使用 `aria-live` 和 `aria-busy`。

## Responsive and accessibility

桌面与 390px 移动视口都必须满足：主文档无水平溢出，任务和提交面板不越界，商品表格仅在自身区域滚动。表格滚动区域有 `role="region"`、可键盘聚焦和明确标签；表格 caption 对视觉隐藏，对读屏保留。

筛选按钮维护 `aria-pressed`，状态不依赖颜色，装饰图标隐藏于辅助技术。减少动态偏好会关闭动画和过渡。

## Copy rules

- 控件写具体动作，例如“立即只读复核”“确认设置并继续”。
- 授权任务的复核备注明确说明不会修改门店、账号、商品或价格；更正门店使用新的任务表单。
- “未返回”“未确认”“未授权”保留原本的不确定性，不改写成失败、零库存或停售。
- 平台建议价格不描述成已采用的秒杀价。
- 只有两轮业务结果核对一致时，任务才能表达为已核验成功。
